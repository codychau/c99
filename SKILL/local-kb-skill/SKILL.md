# local-kb-skill

一个命令行 HTTP 客户端（与本文档放在同一目录分发的可执行文件），用于向 **C99 本地知识库 HTTP 服务**（默认 `http://127.0.0.1:9527`）发起知识库检索提问，并取回基于库内资料的 AI 回答。可执行文件与本 `SKILL.md` 同目录，无需安装或构建，直接调用即可。

## 何时使用本 skill

- 需要从本地知识库中检索资料来回答用户的问题，而不是只凭模型自身知识回答时。
- 需要验证本地知识库服务是否在线（健康检查）。
- 需要在脚本 / 自动化流程中以命令行方式查询知识库。

## 可执行文件位置（重要）

可执行文件 **就放在本 `SKILL.md` 所在目录**，与本文档一并分发，**不会安装到系统 PATH**。因此**不要**直接写 `local-kb-skill ...`（会报“不是内部或外部命令”/“command not found”），必须使用可执行文件的路径来调用。

调用前先确定本 SKILL.md 所在的目录（下面记为 `<skill目录>`，Windows 下文件名为 `local-kb-skill.exe`，Linux/macOS 下为 `local-kb-skill`）：

- Windows（PowerShell / cmd）：
  ```powershell
  .\local-kb-skill.exe --health
  ```
- Linux / macOS（bash）：
  ```bash
  ./local-kb-skill --health
  ```
- 在任意工作目录调用时，请带上完整或相对路径（路径以实际分发位置为准），例如从本文件所在目录调用：
  ```powershell
  .\local-kb-skill.exe --health
  ```

> 对 AI 的硬性要求：执行本工具前，先用文件系统工具确认本 SKILL.md 的同目录可执行文件的确切路径（Windows 追加 `.exe`），再以该路径运行。下面所有示例中的 `local-kb-skill` 均代表“skill 目录下的可执行文件”，实际执行时请替换为上述真实路径。

## 前置条件

查询前必须满足（否则会返回错误或空结果）：

1. C99 应用的 **AI 梦工厂 HTTP 服务**已启动（即 AI 梦工厂页面点击「▶ 启动」，监听 `http://127.0.0.1:9527`）。
2. **知识库已连接**：C99 应用的知识库页面已点击「🔌 连接」，且至少有一个集合（collection）已建立并写入过文档（入库）。
3. 配置了可用的本地/外部大模型（`/api/kb/query` 会先检索资料、再由 AI 依据资料生成回答，可能需要较长耗时，通常数秒到上百秒）。

本目录下的可执行文件与 `SKILL.md` 一并分发：Windows 为 `local-kb-skill.exe`，Linux/macOS 为 `local-kb-skill`，在命令行中直接使用文件名即可。

## 用法

```text
local-kb-skill [选项] <问题...>
local-kb-skill --health [选项]
```

| 选项 | 说明 | 默认值 |
| --- | --- | --- |
| `-u, --url <地址>` | 服务地址 | `http://127.0.0.1:9527` |
| `-c, --collection <名称>` | 指定知识库集合名；留空由服务端自动选择 | 空 |
| `-k, --top-k <数字>` | 检索召回条数（>=1） | `8` |
| `-t, --timeout <秒>` | 单次请求超时（检索+AI 生成可能较慢） | `120` |
| `--health` | 只做健康检查（`GET /api/health`） | — |
| `-h, --help` | 显示帮助 | — |

## 示例

健康检查（确认服务在线）：

```bash
local-kb-skill --health
# {"status":"ok","model":"local-model"}
```

基础提问：

```bash
local-kb-skill "公司最近发布了哪些产品？"
```

指定集合与召回条数：

```bash
local-kb-skill -c "产品资料" -k 8 "Q4 的产品路线图是什么？"
```

问题带空格的完整写法（务必用引号包裹）：

```bash
local-kb-skill --question "请结合知识库说明：如何配置向量模型？"
```

## 底层 API 契约（供 AI 参考，无需手动调用）

服务端为 OpenAI 兼容的本地 HTTP 服务，本客户端封装了以下端点：

### GET /api/health

```json
{ "status": "ok", "model": "local-model" }
```

### POST /api/kb/query

请求体：

```json
{ "question": "公司最近发布了哪些产品", "top_k": 8, "collection": "" }
```

成功响应（`200`）：

```json
{ "answer": "基于知识库资料生成的回答文本……" }
```

失败响应：

```json
{ "error": "问题不能为空" }
```

- 空 `question` → `400`。
- 服务端内部异常 → `500`（响应体含 `error` 字段）。
- 当知识库未连接 / 无数据时，`answer` 可能为提示性文本或空结果，需如实告知用户，不要编造。

## AI 使用指引

1. **先确认服务在线**：用上文「可执行文件位置」中的真实路径执行 `--health`（例如 `.\local-kb-skill.exe --health`）；失败说明 9527 服务未启动，应提示用户先启动 C99 的 AI 梦工厂 HTTP 服务并连接知识库，不要继续提问。
2. **构造提问**：把用户问题原样或稍作改写后作为 `<问题>` 传入；默认召回 8 条即可，问题较宽泛时可调大 `--top-k`。
3. **获取回答**：程序把 `answer` 直接打印到标准输出，AI 应把该回答作为检索到的依据呈现给用户，并注明来源为本地知识库。
4. **错误处理**：
   - 退出码 `1`：用法错误，检查参数。
   - 退出码 `2`：服务端错误，把错误体展示给用户并给出建议（如检查集合名、是否入库）。
   - 退出码 `3`：网络/连接失败，多半是服务未启动，提示用户启动服务后重试。
5. **结果为空 / 找不到**：如实告知用户「知识库中没有相关资料」，禁止编造。

## 退出码约定

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 用法错误（参数缺失/非法） |
| `2` | 服务端返回错误（HTTP 4xx/5xx，或响应解析失败） |
| `3` | 网络 / 连接等运行时错误 |

## 注意事项

- 所有文本均为 UTF-8；中文问题/回答无需转码。
- 提问时优先复用调用者的原始问题，避免过度改写丢失关键实体词。
- 长回答请保留完整，不擅自截断；需要摘要时在拿到 `answer` 后再做二次处理。
